ConstraintProblem

Schema anomalies found

  • VERIFIED Sale::$fillable lists deliveryman_id, kot_id and isPaid, but the sales table has none of these columns → any code path assigning them would fail or silently drop data. There is no delivery-person model at all.
  • VERIFIED sales has no columns for delivery charge, service charge, packaging, tip or per-line tax; these are not first-class fields (likely inside sale_data/meta JSON — INFERENCE). This makes tax and charge reporting on JSON fields fragile.
  • VERIFIED Seed data is internationally generic: payment types Cash, Card, Bank, Bkash, Nagad, COD (Bangladeshi wallets), gateways Stripe/Mollie/Paystack/Razorpay/Instamojo/Toyyibpay/Flutterwave/Thawani/Tap. UPI is not a seeded payment type; Indian tenants must create it manually.
