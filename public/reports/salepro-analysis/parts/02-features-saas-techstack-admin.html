How offline POS works (what is known)

  • Vendor says: "Offline first with sync … keep taking POS sales during temporary connectivity loss and sync when the connection returns" VERIFIED FACT. The UI shows a cloud icon (online/offline) with a pending-sale count badge VERIFIED FACT.
  • Documented (Part 12): products are cached in the browser while online; the POS switches to offline automatically and hides online-only options; sales are saved in the same browser, an offline receipt can print, and sales sync one by one on reconnect (failures stay pending). Not documented: storage engine, customer/price/stock caching, invoice numbering while offline, stock conflict rules, maximum offline duration, whether KOT/tables/KDS work offline UNKNOWN.
  • Limits: the docs themselves warn it is tied to one computer/browser and that clearing browser storage before sync can lose sales VERIFIED FACT. Inferred INFERENCE: stock can oversell on reconnect; gateway payments, QR orders and cross-device KDS cannot work offline; invoice-number collisions are the classic risk.
  • Indian restaurants/retail: restaurants need KOT→kitchen printer/KDS on the LAN even when internet drops; a browser queue on one device does not give that. Petpooja solves it with a local Bridge Server (see gap-analysis Part 04). SalePro's model is therefore PARTIAL for single-counter retail and NOT proven for multi-terminal restaurants INFERENCE.

6. Admin panel (what we get out of the box)

Super admin — confirmed VERIFIED FACT

  • Dashboard: estimated MRR, active paid vs total clients, renewals due in 30 days, revenue/subscription charts.
  • Clients: create tenant with subdomain; renew; change package; change tenant password; assign custom domain; activate/deactivate; back up tenant DB; update tenant DB.
  • Packages: monthly/yearly price, limits (warehouses, products, invoices, users, employees), module toggles, sync to existing tenants.
  • Payments: manual + gateway settings (sandbox/live, keys, callback URLs); failed payment monitoring recommended in docs (manual).
  • CMS, blog, SEO, analytics scripts, themes; affiliates; support tickets; mail (SMTP); general settings (title, logo, currency, trial length, disable signup/tickets); add-on installation.

Super admin — needed for our business but not found UNKNOWN/NOT FOUND

Churn and ARR reports, cohort/retention, per-tenant usage metering (DB size, storage, API calls, WhatsApp/SMS usage), system-health page, feature flags beyond packages, audit log of super-admin actions, login-activity/IP/device tracking, 2FA for super admin, impersonation ("login as tenant") with audit, dunning automation, tenant-facing invoices with GST, tenant export/delete tooling, reseller/partner accounts (affiliate is not the same as reseller with tenant management).
