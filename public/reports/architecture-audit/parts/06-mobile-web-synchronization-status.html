Overall read

For the operational POS/back-office surface that both apps target (auth, catalog, POS, billing, inventory, customers, HRM, reports), mobile is genuinely well-synchronized with the backend — roughly 80–85% endpoint coverage, because the mobile app was built directly against this backend's real API from the start, not against a mock or a divergent schema. The two real integration gaps are structural, not incremental: Multi-branch and Cash Register are entire backend modules with no mobile presence at all, which matters because Multi-branch in particular is core to a multi-location restaurant SaaS. The rest of the gap is a handful of specific endpoints (refresh-token, change-password, module-check) the mobile client should start calling rather than new backend work.
