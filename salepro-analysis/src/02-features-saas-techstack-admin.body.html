How offline POS works (what is known)

  • Vendor says: "Offline first with sync … keep taking POS sales during temporary connectivity loss and sync when the connection returns" [[V]]. The UI shows a cloud icon (online/offline) with a pending-sale count badge [[V]].
  • Documented (Part 12): products are cached in the browser while online; the POS switches to offline automatically and hides online-only options; sales are saved in the same browser, an offline receipt can print, and sales sync one by one on reconnect (failures stay pending). Not documented: storage engine, customer/price/stock caching, invoice numbering while offline, stock conflict rules, maximum offline duration, whether KOT/tables/KDS work offline [[UNK]].
  • Limits: the docs themselves warn it is tied to one computer/browser and that clearing browser storage before sync can lose sales [[V]]. Inferred [[INF]]: stock can oversell on reconnect; gateway payments, QR orders and cross-device KDS cannot work offline; invoice-number collisions are the classic risk.
  • Indian restaurants/retail: restaurants need KOT→kitchen printer/KDS on the LAN even when internet drops; a browser queue on one device does not give that. Petpooja solves it with a local Bridge Server (see gap-analysis Part 04). SalePro's model is therefore PARTIAL for single-counter retail and NOT proven for multi-terminal restaurants [[INF]].
