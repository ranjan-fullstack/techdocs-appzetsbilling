Mobile-side architecture gaps

  • No offline support — connectivity_plus only blocks the UI on disconnect; no local DB, no request queue, no write cache. Significant for a restaurant POS.
  • No environment/flavor split — a single hardcoded production URL is baked into the binary.
  • Release APK signed with the debug keystore (signingConfig = signingConfigs.debug in android/app/build.gradle, with a TODO left in place) — a release-readiness gap, not just architectural.
  • No refresh-token flow — a single long-lived opaque bearer token in plain shared_preferences; no JWT decode/expiry check client-side, session end relies on server-side 401.
  • No FCM token-refresh handling — the token is sent only at sign-in/sign-up; a rotated token post-login is never re-synced to the backend.
  • Two different error-handling shapes coexist (Either<String,T> vs. bare throw Exception), and provider placement is inconsistent across features — no single house style, though the vertical layering itself is consistent.
  • Thin automated test coverage (6 files) relative to app size.
