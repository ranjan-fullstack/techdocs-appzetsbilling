What's already right and should not change

  • One backend, one database, one API. Mobile should keep authenticating and reading/writing through https://app.appzetsbilling.com/api/v1/* exactly as it does today — do not stand up a second backend or a mobile-only database.
  • Sanctum + spatie/laravel-permission as the single auth/authorization mechanism for both clients.
  • The module system (nwidart/laravel-modules) is a reasonable way to keep Inventory/HRM/MultiBranch/CashRegister decoupled; mobile should adopt the same module-awareness (via /module-check) rather than hardcoding which features are visible.

What needs to change

  1. Confirm and, if needed, converge web's data path. If the Blade panel bypasses /api/v1 with separate controllers, that logic should be consolidated so the API controllers are the single source of truth for business rules (tax, discounts, stock deduction), with Blade views calling the same API internally or via shared service classes — not reimplementing the rules.
  2. Move tenant isolation from "remembered per-controller" to enforced-by-default — an Eloquent global scope (or a base repository/trait) keyed off the authenticated user's business_id/branch_id, so a forgotten where() can't leak another tenant's data. This matters more, not less, as mobile drives more traffic through the same endpoints.
  3. Turn on what's already configured: a queue worker (Supervisor + artisan queue:work), the Laravel scheduler (* * * * * php artisan schedule:run in cron), and a real decision on Pusher/Soketi if realtime is wanted (§13).
  4. Give mobile an environment-aware build (dev/staging/prod via --dart-define, see §16) instead of one hardcoded production URL.
  5. Deliberately scope Multi-branch and Cash Register for mobile — build against the existing branches/switch-branch/register endpoints rather than treating the gap as acceptable by default.

This keeps the backend as the sole source of truth for business rules (tax, stock, pricing, permissions) as required, with both web and mobile as thin, replaceable clients of the same API.
