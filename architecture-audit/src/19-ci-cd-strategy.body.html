Today: no CI/CD pipeline was found. The production app directory is a live git working tree (origin = a real GitHub repo) that appears to be pulled/pushed to directly on the VPS — deploys happen by editing or syncing the production server itself, evidenced by a recent commit made in that working tree ("sync: VPS server working tree state"). There is no build/test gate before code reaches production, and no staging environment to catch issues first.

Recommended pipeline (proportionate to a 39-tenant SaaS — not enterprise-scale tooling)

git push (feature branch)
  -> CI: backend tests (phpunit) + mobile tests (flutter test) + lint
  -> merge to main
  -> CI: deploy to staging (backend) automatically
  -> manual smoke test on staging
  -> tag release -> CI: deploy to production (backend)
  -> mobile: CI builds signed APK/AAB (and iOS build) -> internal testing track -> store release

Backend

  • Move off "edit/pull directly on the VPS" to a proper deploy step: GitHub Actions (or similar) that SSHes in, pulls the tagged commit, runs composer install --no-dev, php artisan migrate --force, php artisan config:cache, and restarts PHP-FPM — all scripted and repeatable, never manual.
  • Gate merges to main on phpunit passing (once the test suite in §18 exists).
  • Stand up the staging environment from §16 as the pipeline's first deploy target.

Mobile

  • CI job running flutter analyze + flutter test on every PR.
  • CI build producing signed Android App Bundle (fixing the debug-keystore issue from §15 as part of this work) and, if iOS is targeted, a signed IPA — using --dart-define per §16 to select the environment per build.
  • Automatic distribution to an internal testing track (Play Console internal testing / TestFlight) on merge to main, manual promotion to production release.

Sequencing note

CI/CD and the staging environment (§16) are prerequisites for safely shipping most of the rest of this roadmap (branch support, offline sync, refresh-token adoption) — recommend standing these up early (Roadmap Phase 0, §20) rather than bolting them on after feature work is already underway.
